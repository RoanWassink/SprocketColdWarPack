# Keybinds 0.1.10 handoff

Built in the isolated work directory against the 2026-11-13 reference-only gameref. No installation or publication. The framework core now includes a pure managed global settings registry with config-backed values, cached immutable author/pack snapshots, safe visibility and presenter hooks; a second native launcher; an unbound open action; and live DetailedLogging (default false). The UI Kit builds the settings panel separately. Capture/Reset prefixes fall back to vanilla on errors; all 10 patch targets and Cancel/Esc behavior are retained. Protected input sources and Keybinds.cs remain byte-identical.

Final FIX1 validation: core and consumer builds each have 0 warnings/errors; 376 checks pass with the existing enum-list construction SKIP; 44 baseline ABI entries remain and 70 additions are exported. All ten patch targets retain unique RVAs. Full results are recorded in logs/validation-summary.md; logs/artifact-sha256.txt contains the current DLL hash. The version remains 0.1.10. All optional logging initialization is guarded, followed by a shared guard for metadata, shortcut and settings registration; polling tolerates missing handles. ModSetting presentation members are getter-only properties and SettingOptions members have public get/set accessors.

Validation evidence is in logs/: release and consumer builds, managed regression/settings checks, full public API additions, patch-target RVA table and diffstat. The ABI baseline is 0.1.9 with the brief's SHA256 prefix and 44 exported entries. Real BepInEx cfg files prove managed type descriptions, mutation, persistence and reset; snapshots and exceptions are covered without native UI. The pure harness replaces only the Keybinds.Metadata holder. Object and KeyboardShortcut refusal use ConfigEntryBase instances attached to a real ConfigFile, avoiding unsupported serializer/native initialization.

Unproved without a game run: native row cloning/layout and clickability, presenter state changes across Attach/Refresh, the action's in-game polling, both native fallback error paths, consumers loading together, UI Kit rendering, and Settings/Esc interaction. Pure tests and unique RVAs do not prove native execution. The row requests deferred presentation: the UI Kit must wait until Settings is closed before displaying the panel. Keybinds does not enforce that Kit policy; its native Cancel/Esc path remains unchanged. The delayed display and paused-game transition still need a joint Kit game test. Mods remain responsible for live cfg reads or RequiresRestart.

Validation deviations: the reference BepInEx generic constraint prevents instantiating AcceptableValueList<TEnum>; enum-list subset construction is explicitly SKIP. Normal enum names/aliases and string/numeric acceptable lists are tested. Initial test compilation exposed the listener filter and enum constraint; assertions then exposed a warning-count expectation and section order after removing/re-registering an entry. The harness was corrected and persistent section order was added; affected checks were rerun. Earlier output is retained in logs/test-attempts.log.

Validation deviation: the required name-scan log name and checker header themselves contain the forbidden personal token. The checker therefore excludes logs as well as its standard bin/obj/.git exclusions; source, documentation, examples, tests and the new DLL are scanned without added exceptions. Log paths are normalized. The brief overrides skill requirements to write external status/skill files, so no files outside this workspace are updated. Route: single Codex builder with local checks. FIX1 diffstat is relative to obj/fix1-baseline (the previous delivery), while protected-source and ABI tests retain their original baselines.
