# Boss character AI — 24 October 2026

Status: implemented; pure boss-policy checks pass. Native character behavior has not been playtested. The coordinator integrates encounter/reward/content metadata and performs final game builds and installation.

## Binding and calls

After `CampaignEnemyHunt.Prepare(config, planHash)`, call `CampaignBossTactics.Prepare(actualNativeTankName, character)` only for a boss encounter. Hunt preparation releases the old encounter; preparing the boss before Hunt would therefore clear it. Character labels are Fortress, Hunter, Battery and Veteran. The actual native name is read from `VehicleBehaviour.VehicleInfo.TryCast<Vehicle>().DesignInfo.Name`, using verified current interop members (`Sprocket.Vehicles.Vehicle`, `IVehicleInfo.Name`). It is not a GameObject name, unit label or catalogue alias.

The live adapter waits for the requested enemy roster and readable native names, then accepts only one exact ordinal enemy design-name match. Friendlies never qualify. No match, duplicate matches, or a later matching hull with another native pointer disables character assignment; no nearest/first/arbitrary hull fallback exists. A destroyed boss cannot silently transfer its character to another hull. The placeholder boss should consequently have a unique actual design name when escorts use the same underlying design.

`CampaignEnemyHunt.Release()` releases boss preparation as well. Transient load polling resets live claims while preserving the pending configuration, as required for the same battle load. No save contracts, native blueprints, stats or file paths are modified by this AI helper.

## Characters

- Fortress uses the native Passive approach and StopToFire when it has a currently visible target. Existing rally movement is replaced by the attack order; no new tactical advance waypoint is issued while that target is visible. This is a native hold/fire intent, not a physics position lock.
- Hunter uses native Aggressive approach and keeps firing on the move down to 140 m; after stopping, it stays stopped until 200 m. Existing native visibility/target-choice rules still apply.
- Battery uses native Passive/StopToFire by default. A currently visible target within 220 m can trigger a fixed short withdrawal, at most 50 m away from that observed location. The endpoint must pass terrain, slope and native map-bound checks with 16 m margin, plus unobstructed path rays at 1.2/2.4 m height beyond the hull's first eight metres. If qualification fails, it holds/fires instead. A successful leg lasts at most 24 s and has a 36 s restart interval; the fixed endpoint does not track hidden subsequent movement. Native FireAtWill stays enabled; weapon operation and firing opportunities remain native.
- Veteran uses native Balanced approach and the existing 280/340 m stopping hysteresis.

Before seeing a target, each character uses the accepted mutual-spawn rally and contact-memory/search policy. No role changes health, armour, firepower, accuracy, cost, era dates, target visibility or native tank physics. Scope remains the currently owned Expedition battle; native player orders and control handoff retain precedence.

The current native `CommanderAI.GetIdealCombatPlan` was inspected locally (RVA 0x201a8a0): Passive returns no autonomous close/flank plan, Aggressive selects native closing/flanking, Balanced retains the native adaptive branch. Research remains local under `artifacts/boss-ai-20261024-before` and must not enter distributable packages or external model context.
