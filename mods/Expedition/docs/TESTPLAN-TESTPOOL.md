# Test pool (0.3.1)

1. With the game closed, use the separately reviewed 0.3.1 campaign build. This workspace does not install it.
2. Place all supplied `.blueprint` files in `BepInEx\config\SprocketExpedition\test-pool\`; retain originals. The source folder contained 35 files at verification (the brief listed 33).
3. In `BepInEx\config\sprocket.expedition.cfg`, set `[Campaign] TestPool = true`, then start the game.
4. Open New Game and wait for validation. Expect `TEST POOL ACTIVE: N tanks (enemies only from test pool)`. Check `BepInEx\config\SprocketExpedition\stats\test-pool-report.csv`: every input file has a row, rejected files have a reason. Fewer than three accepted distinct tanks blocks the new test run.
5. Start a new run in any era. Expect three TEST cards with the first three accepted tank names in alphabetical order, one enemy each, even if their era or price exceeds yours. Your starter and player budget follow normal rules.
6. Choose a card and fight. Record whether the named tank appears, moves, fires and can die. Keep the exact name with each finding; native card acceptance alone does not prove these behaviors.
7. Lose, retreat or return before contact, then retry. The same three cards and names must remain; no rotation advance, extra funds or loot. Ironman still ends on defeat. (Superseded in 0.3.4: a loss or retreat now advances to the next tanks; see [TESTPLAN-0.3.4](TESTPLAN-0.3.4.md).)
8. Win a normal round: the next three names appear. Round four offers one BOSS/TEST card for the next tank, one copy, with the existing boss presentation/music. After winning it, the cursor advances by one. Continue, including endless if needed, to wrap through all accepted names; boss rewards/items still work.
9. Save and reload a test run after changing the config to false and moving the source test folder aside. The archived test run retains its pool, rotation and TEST identity. Existing normal runs must stay normal even when config is true.
10. Complete an era and retire the test run. No new veteran archive is created. Records display TEST and the record payload contains `test_pool: true`.
11. Inspect `stats\battles.csv`: trailing columns are `test_pool,enemy_designs`, with 1 for test runs, 0 for normal runs and names joined by `|`. Previous rows retain their values; new columns are empty on migrated rows.
12. Give Opus the per-tank results, report CSV, battles CSV and `BepInEx\LogOutput.log`. Relevant lines: `Expedition test pool: rejected <file>: <reason>` and `Expedition test pool: battle <round> enemies=<names> outcome=<outcome> spawned=<n>/<m>`. The spawn numerator is the HUD roster's observed enemy count, retained across deaths; compare existing host roster, hunt/weapon and outcome traces for firing/death evidence. Set TestPool false before starting ordinary runs again.
