# Coordinator decisions after the contract preflight

2026-10-17. A preflight review of the sanitized project texts produced 17 findings and 40 proposed acceptance cases. These are review findings, not executed tests. No game/native data was sent. Changes below are design decisions for the contract freeze.

**2026-10-20 freeze:** the native vertical-slice core gate has passed live: player/ally/enemy spawning, one win and one loss, native editor return, repeated restart (13 clean restores) and post-loss editor restoration. `src/SprocketExpedition.Core/Contracts.cs` is frozen as Core contract v1.0, including `FriendlyForceDestroyed`, `CombatRetreat`, `PrecombatAborted`, `AttemptIdentity`, `OfferRequest` and `IEncounterCatalogue`. The broad implementation gate is OPEN for Core workers 3A/3C. Non-blocking acceptance checks (ally orders/friendly fire, leave during loading, mod/ERA reload, normal editor Play) remain for integration/live acceptance.

| Finding | Decision |

| F1 attempt generation | Accept. Persist a monotonic generation per attempt; retry and crash recovery use a new generation while preserving the exact plan. Cleanup invalidates the old attempt before any new one starts. |
| F2 simultaneous outcome | Revised 2026-10-20: destruction of **all friendly vehicles** dominates elimination victory in the same authoritative simulation update. Destruction of the original player tank alone is not defeat; native control may continue in a surviving friendly. Adapter consolidates state after that update and emits one result. Core never retroactively rewards an earlier provisional victory. Actual native ordering must be measured before integration. |
| F3 abort taxonomy | Accept. Distinguish PrecombatAborted, CombatRetreat and TechnicalFailure. Loading cancellation has no reward/loss; deliberate exit from live combat is loss. Process crash recovers same fight as specified. |

| F9 content dependencies | Accept. Persist selected plan's complete required-mod union (player, enemies, map) plus catalogue version and local content hashes. Check before load/resume; missing content blocks without rewriting save. |
| F10 snapshot payload | Accept. Adapter captures/restores opaque native snapshot with format/version/hash; storage owns bytes/hash validation. Freeze native format only after actual serialization evidence. No assumption that Header.Cost or handwritten JSON equals a valid mod-preserving snapshot. |

## Ownership amendments

-3A defines RunSnapshot, but its serializable shape must be frozen by coordinator before3B starts.3B is not initially parallel with3A.
-3C needs a frozen offer-generation input/result contract before parallel implementation.3A accepts generated offers; it does not also generate them.
-3D starts only after controller/presenter and tested native UI host are available. Native owner hands off Game/UI explicitly.
- Runtime models, snapshots, saves and UI must not independently derive native era or costs.
- The next contract review adds these decisions to types only after the native vertical slice is proven. This is intentional: premature finalization could encode incorrect snapshot/cost/lifecycle semantics.

## 2026-10-20 worker integration notes

- **Threat ownership:** 3C's `EncounterRules.ThreatTarget` applies the within-block multiplier `[.65,.90,1.15]` and the risk multiplier `[.9,1,1.15]` to the supplied current fleet ceiling. 3A supplies that ceiling, already including the active supply bonus, and must not apply either multiplier again.
- **Supply input:** `PendingSupplyPoints` is display/telemetry; it must not be added to `AvailableBudget` a second time. F14's `103 = 100 + 3` case is represented by the supplied ceiling.
- **Endless:** the catalogue infers endless from `Block > 6` and `BlockForRound`; it never invents a native era or date. 3A passes the block explicitly.
- **Interface gap:** Core contract v1.0 keeps `IEncounterCatalogue.GenerateOffers`/`Find` narrow. Availability/exhaustion results, `RestoreOffers` and `MarkResolved` currently live on the concrete `SeededEncounterCatalogue`. Integration must review whether a v1.1 contract amendment is needed after 3A/3C; no worker may change `Contracts.cs` silently.
- **Content:** `content/example.catalogue.json` is explicitly `TEST FIXTURE NOT PLAYABLE`. Release still requires three checked maps and at least four checked enemy designs per native era.
- **`ReportCombatStarted`:** accepted as an engine lifecycle signal. It is required to distinguish `PrecombatAborted` from `CombatRetreat` and to persist an observable `Fighting` phase. It is not a change to `Contracts.cs`.
- **`Resolving`:** not persisted. `AcceptResult` applies the authoritative outcome atomically; there is no half-applied reward snapshot.
- **`RunSnapshot` v1.0:** frozen for 3B in `docs/run-snapshot-freeze.md`. Fields and conventions are fixed; any addition is a v1.1 schema decision.
- **3B persistence:** merged and 30/30 green. GUID run ids, SHA-256 blueprint hashes, exact ordinal mod matching, atomic checkpoint/backup/index, and terminal saves clear both `activeRunId` and `checkpointHash`. Exact terminal duplicates are inert (`Unchanged`); a different terminal snapshot is `TerminalImmutable`.
- **Adapter capture:** `IGameAdapter.CaptureDesignAsync` takes the build block's `EraReference` and returns `DesignCapture` (measured quote plus opaque native snapshot bytes, kept out of the presenter). `RunEncounterAsync` takes a `combatStarted` callback so the controller can persist the Fighting boundary and distinguish precombat abort from combat retreat. The Game scaffold captures the native serializer bytes and quote; the encounter runner is still a deliberate `TechnicalFailure` until dynamic authored spawning is live-qualified.
- **Block indexing:** `RunSnapshot.BlockIndex` and `OfferRequest.Block` are both zero-based. 3C's `EncounterRules.BlockForRound` was corrected to return zero-based and its tests updated; this resolves the earlier 3A/3C mismatch.
- **Phase 4 controller:** `ExpeditionController` is implemented with start/resume/offers/selection/begin/result/continue/retry/endless/finish/suspend/recover and the `DesignCapture`/combat-start boundary. `tests/Integration` passes the fresh-start, resume, victory, loss and technical-retry scenario with a real `RunStore` and scripted adapter/catalogue/presenter.
- **Open v1.1 seams:** explicit `AbandonCurrentRun`/archived `Abandoned` run (F6) and an endless-content-exhaustion completion signal. They must not be silently represented as a combat loss or added to the frozen snapshot without a schema decision.
