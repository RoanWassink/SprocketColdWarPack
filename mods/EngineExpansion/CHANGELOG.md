# Changelog

## 0.5.0 - 2026-11-08 (junction collapse, Leopard eligibility fix, integrated casing; prepared build)

- Powerpack.Layout.CollapseJunctions=true recognises single-input/single-output junction chains ending at one gearbox or a single splitter and mirrored gearbox pair. Removed mirror junctions must occur together. Manual splitters are normalised to native 0x70. MaxCollapseDistance defaults to 1.75 layout metres, measured engine output to each gearbox input (maximum for Twin): Challenger 1 needs 1.701 m. Remote/front-drive Panzer IV routes are refused. False uses the unchanged 0.4.1 recognisers.
- Legacy eligibility is preserved: a layout that 0.4.1 already accepted through direct engine-to-gearbox or exact Twin bypasses the new distance/front-drive gate. Those gates apply only to chains newly collapsed by 0.5.0. Result over the 154 fixtures: **57 ready in 0.4.1, 123 ready in 0.5.0, 0 ready-to-grey**. The 15 Leopard 1/2 blueprints that the draft gate would have greyed are genuinely saved with remote gearboxes and front sprockets (the saved front axle is at +Z), not a space/sign bug; they stay ready. `work/LEOPARD-COORDINATES-0.5.0.md` records engine output, gearbox inputs, sprocket pivots, front axle and the per-fixture conclusion.
- The existing single native copy-swap operation removes junctions, connects surviving ports with IDs above the original global maximum, then applies existing flags and placement. Undo retains the original full layout; unticking restores shafts without resurrecting junctions. No blueprint field or Harmony target added.
- Before assignment, check references, new abstracted TooLong/TooThick, short shafts, angles and conservative bounds overlaps for downstream shafts and moved modules. New problems cancel the edit and explain the reason in the tooltip and one DetailedLogging line. Bounds preflight can refuse geometrically valid layouts; native rebuild/save/load/undo remain in-game acceptance gates. It uses the currently built component bounds; model/port regeneration after assignment still needs live validation.
- Date, branch, front-drive, distance and flag conflicts have explicit tooltips. DetailedLogging emits one collapse line and one collision-mode line per executed toggle; the old per-placement trace is removed.
- Collision decision (2026-11-08): the native engine/gearbox collision remains, with 1 mm placement; the casing covers the seam. There is **no `EngineGearboxCollision` option and no collider-layer switch**. The 0-gap variant is not built. Existing 0.4.1 obstruction volumes are unchanged and no volume is left unchecked. See work/COLLISION-0.5.0-BEWIJS.md.
- Without EE, a saved native auto-positioned powerpack may put its gearbox approximately 0.35 m inside the engine and show "obstructed" while remaining driveable. This is existing native behaviour, not a new blueprint format; a collapsed route stays collapsed without the mod.
- Unknown/unreadable GameAssembly hash enters explicit safe mode with ZERO hooks, hence no short or frame-path hooks. The single warning states the disabled features and that saving can remove EE selections and dormant turbo metadata. A metadata-preserving subset would require the prohibited 54-byte EngineBlueprint.Load (and 117-byte VehicleComponent.LoadData for legacy metadata), so it is not installed on an unknown image.
- EPP casing is integrated as render-only children of the powertrain: LOD0 (556 triangles) and LOD1 (152) are embedded as `casing-lod0/1.meshbin`, SHA256-checked like the other 22 payloads, and warped by the production CasingFit from the engine rear face to the gearbox box. It uses the native engine material and layer, has no collider, is retired before every rebuild, is never duplicated, and is removed by the existing unique `VehiclePowertrain.Clear` prefix (never `VehicleComponent.Release`). Twin places the casing and the existing bridge together, with the bridge lowered below the casing hood to avoid coplanar flicker. `Powerpack.Model.Casing` defaults to true; `Powerpack.Model.Enabled=false` removes it. The exact V12/Renk dimension PNG is `mtu-model/model/shots/casing-fit-v12-renk.png`; `preview-casing-fit.py` and `view-casing-fit.scad` reproduce it from the embedded payload. No installation performed.

## 0.4.1 - 2026-11-03 (ICF startup fix)

- Removed the VehicleComponent.Release bridge hook: IL2CPP folds its empty body with unrelated methods, causing the startup access violation. The existing unique VehiclePowertrain.Clear prefix owns teardown cleanup; rebuild/disable still retire the previous bridge before replacement.
- HookCheck now audits every hook against freshly read native Address attributes across all generated assemblies, rejects unapproved shared RVAs, and records target RVA, byte length and alias count. It verifies the current GameAssembly SHA256 and generator input SHA512 before accepting native evidence. No exceptions; all retained hooks are unique.
- Gameplay, assets, configuration, native mass/cost and blueprint format remain as in 0.4.0. Prepared build only; startup and M1–M14 require the coordinator’s installation/game test.

## 0.4.0 - 2026-11-03 (MTU/Renk powerpack, M2+)

- Date-effective V powerpacks use an instance-local cloned EngineModelDefinition, rebound immediately before Generate and restored on disable. Whole crankshaft length defaults to 0.9; size/height/outboard turbo configuration is supported. Inline, radial and gas-turbine engines keep their native model.
- BuildMeshes postfix replaces both LODs, shadow (LOD1) and collision before native Built. Five independent conservative OpenSCAD hulls have 100 triangles each and enclose LOD0/LOD1; reference convex-envelope excess is below 10 mm.

- DetailedLogging reports model dimensions/triangles and the real native gearbox box only when the report changes. DLL resources are SHA256-checked; reproducible STL conversion, independent hull tests, native hook audit, OpenSCAD viewers and visual QA are supplied.

## 0.2.3 - 2026-11-02 (fix: Twin gearboxes thrown hundreds of metres back)

- The engine obstruction box is now converted to **layout space** before it meets module and port positions. Native `VehiclePowertrain.SetModuleTransform` and `ModuleTransformUpdate` convert world to layout with the VehiclePowertrain's own Transform (`InverseTransformPoint`, `Inverse(rotation) * rotation`), and `Port.position` is `module.position + module.rotation * localPosition`. 0.2.2 left the engine box in world space; in the editor the vehicle sits at about z −345, so both gearboxes were placed about 344 m back. The box now goes collider Transform → world → powertrain Transform (centre, rotation and scale).
- The transmission collider's centre/size are taken in the collider Transform's space and converted into the transmission's own Transform when the collider sits on another Transform. On the same Transform (the normal case) the extent is the 0.2.2 value exactly. The `ExtentFor`/`FindTransmission` lookup was already in layout terms (module id plus powertrain pointer) and is unchanged.
- **Safety net:** if the placement against the engine box lands more than 0.5 m (`PowerpackRules.PlacementSafetyNet`) from the 0.2.1 output-plane placement along the engine direction, or is not finite, the 0.2.1 placement plus the 1 mm clearance is used instead, with one `POWERPACK safety net` warning per toggle. A nonsensical placement can no longer become visible.
- Unchanged: the 1 mm clearance, the same depth left and right, the `POWERPACK on/boxes/place/revert` log lines (`boxes` now prints layout space, the same space as `place`), and Clutch braking byte for byte. New unit checks: a vehicle at (0, 1.67, −345.4) with and without a 3° yaw gives the same placement as without offset; the 0.2.2 world-box bug is reproduced and caught; a 344 m shifted box and the user's 0.2.2 log trip the safety net; the 0.5 m boundary; the transmission collider conversion.

## 0.2.2 - 2026-11-02 (fix: Twin "obstructed")

- Twin now places both gearboxes against the engine's **real required-space collider** instead of the nominal engine-output plane. Native 0.2.56.2 creates that collider as a mesh collider (`CombustionEngine.Initiate`, `NewMeshCollider(layer=Engine, type=Selection|RequiredSpace, options=SolidVolume)`), and its rear surface reaches past the output port. The old rule therefore put the gearbox boxes inside it, which native reported as `longitudinalTransmission obstructed` (2x) and `combustionEngine obstructed` (3x).
- The placement projects the furthest engine-box corner along the engine output direction, including the engine's yaw, and puts the nearest corner of the **full rotated transmission box** (collider centre and size on X, Y and Z) 1 mm beyond it. The native box-box test uses 15 axes with a strict `>` and no epsilon, so touching already overlaps; 1 mm absorbs the float32 transform round trip. `PowerpackRules.ObstructionClearance` carries that constant.
- Both sides get the same depth along the engine direction; the lateral coordinate and the input-port height from 0.2.1 are kept. The 3 cm world-Z offset caused by the yawed engine plane no longer means one side sits deeper into the engine, and the two gearboxes remain clear of each other.
- Fixed the 0.2.1 width lookup: it compared `PowertrainComponent.layout` (the `VehiclePowertrain` controller) with `powertrain.Layout` (the layout data), so it never accepted the live collider and always used the 0.2 m fallback. 0.2.2 compares against `powertrain.Pointer`; the real box centre/size is now measured and used.
- `POWERPACK place` now prints the **real engine output port** (the splitter port was printed before). Under `DetailedLogging`, every toggle adds one `POWERPACK boxes` line with the world-space engine box and both transmission boxes (centre, size and rotation) plus the clearance along the engine direction; the placement report remains capped at 16 lines.
- Clutch braking (0.2.0) is unchanged: it places the transmission input port on the engine output and keeps its 0.33 m input stub between the gearbox box and the engine, so it never touched the engine collider. All 0.2.0/0.2.1 checks remain, plus unit checks for the rotated engine box, the full 3D transmission box, the symmetry of the pair and the native 15-axis overlap test.

## 0.2.1 - 2026-11-02 (proefbouw Powerpack, Twin)

- Twin transmission is now supported instead of greyed out. With the engine feeding a splitter junction (native 0x70) and two mirrored transmissions, ticking Powerpack marks both transmissions with `PositionBetweenInputs` (0x1C00) and marks all three connections `Abstracted` (engine to splitter, splitter to left, splitter to right). The splitter keeps its native 0x70 and stays between the gearboxes.
- Twin placement is still native auto-positioning. The `GetModuleAutoPosition` postfix now also handles a transmission whose only input is an Abstracted splitter whose only input is an Abstracted engine: it puts the transmission's motor-side face on the engine output plane, keeps the chosen lateral coordinate, and puts the input port at the engine output height. It reads the engine output, not the splitter, so there is no placement cycle. The transmission width comes from its native box collider (fallback: the native 0.4 m longitudinal width at the current volume scale).
- The width cache now lives for one `VehiclePowertrain.BuildLayout` only: it is cleared before and after the build, so a changed transmission or a reused module pointer never gets the old width. A fallback is returned but never stored, so a `GetModuleAutoPosition` call outside a layout build cannot pin the guess. A marked transmission also raises the native `Geometry` dirty flag after its `Build`; native `SetTransmissionInfo` only dirties the layout when the min/max ratios change, so a torque-only change would otherwise leave the old origin. Geometry re-runs autoposition without re-instantiating modules, and this is per build, not per frame.
- The native loop places the transmissions (IDs 2 and 3) before the splitter (ID 1) because it walks the blueprint module list backwards; the splitter therefore lands in the same pass. The existing second pass remains as a same-frame safety net for downstream junctions.
- One native undo step per click for Twin as well: the layout copy-swap now sets/restores two modules and three connections, and the saved selection.
- Unticking restores the flags exactly. The pair is widened symmetrically (and moved along the engine shaft if needed) so every restored shaft is at least `DriveShaft.MinDriveShaftLength` (0.1 m); the splitter follows to the midpoint on the rebuild. Still one undo step.
- Tooltip: Clutch braking keeps its text; Twin explains that both gearboxes sit against the engine output. Conflict handling is unchanged, except that the splitter's native 0x70 is not a conflict. A partially marked or otherwise conflicting Twin layout is refused.
- Housing mass and cost, `Powerpack.AvailableFrom` and the save schema are unchanged from 0.2.0. Clutch braking behavior is unchanged; the 0.2.0 tests remain in place.

## 0.2.0 - 2026-11-02 (proefbouw Powerpack)

- New engine-inspector toggle **Powerpack** (native ToggleField) next to the engine type. It is available from the vehicle date `Powerpack.AvailableFrom` (default 1965.01.01, provisional); earlier vehicles see `Powerpack (vanaf 1965-01-01)`. The final-era date 9999.12.31 always allows it.
- Ticking it changes only native layout values: the directly fed transmission gets `PositionBetweenInputs` (0x1C00) and the engine to transmission connection becomes `Abstracted` (1). The native auto-positioning then places and follows the transmission, so no code runs per frame. Engine Expansion only puts the transmission's input port, not its centre, on the engine output.
- One native undo step per click (layout copy-swap plus saved selection). Unticking restores the original flags exactly and moves the transmission back by the native minimum shaft length (0.1 m), so a normal shaft returns.
- Twin transmission (engine drives a splitter junction) is not supported: the toggle is disabled there, with a tooltip.
- Housing: +`Powerpack.HousingMassFraction` (0.10) of engine mass and +`Powerpack.HousingCostFraction` (0.15) of engine material cost, only while the powerpack is date-effective. A saved powerpack on a too-early vehicle keeps its layout; only the housing lapses, with one warning.
- Save metadata schema 2 (`Powerpack`) is written only for powerpack engines; schema 1 reads as no powerpack, and unknown schemas are preserved byte for byte.
- New `Diagnostics.DetailedLogging` (default true) gates the existing SYNC/PROFILE trace lines and the new POWERPACK lines.
- `TransmissionVolumeMultiplier` and all other 0.1.1 behaviour are unchanged.
